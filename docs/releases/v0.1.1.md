# Pi Durable Platform v0.1.1

A fix release (2026-10-18) on top of [v0.1.0](v0.1.0.md): small console fixes found while preparing the documentation
and screenshots, `doctor` checking the agents database, a read-only console path for platform staff to any team's
agents, and the product's logo. No database migrations (still `00016`), no configuration changes.

## What changed

**Added**

- **`doctor` checks the agents database.** It connects to `AGENTS_DATABASE_URL` and checks that its role can provision
  agents (`CREATEROLE`, and `CREATE` on the database, on PostgreSQL 16 or later). Skipped without an agents database;
  reported as info when `AGENTS_CREATE_DATABASE` will create it.
- **Platform staff read any team's agents.** Platform admins and auditors see every team's agents read-only
  (`GET /v1/teams/{team}/agents`, `GET /v1/agents/{id}`), not only personal workspaces'. Admin › Teams › a team has an
  Agents tab linking to each agent's page: Overview and Settings, Conversations for platform admins (reading one still
  takes a reason), and no Test.
- **The product's logo, "Wake".** The sidebar, the sign-in page and the session-unavailable page show Pi Durable
  Platform's mark when the instance has no logo of its own (`UI_LOGO_URL` still replaces it); the favicon is the mark,
  with a `favicon.ico` and an `apple-touch-icon.png`.

**Changed**

- **Staff can't hibernate other teams' agents.** In v0.1.0 platform staff could hibernate a personal workspace's agent
  (`POST /v1/agents/{id}/hibernate`); now only the agent's team can, and staff get 403. Staff access to agents is
  read-only everywhere.

**Fixed**

- Sign-in: the "Help signing in" link uses the app's link colour.
- Home: the Agents card no longer shows an empty strip (it links to All agents and the Catalog).
- Admin › Models and MCP servers: the Owner filter's chevron no longer overlaps its text (every small select).
- Admin › Templates: the review queue and the full list each have a heading, and the queue's table a name.
- Admin › Settings › Private networks: the example placeholder shows only while no network is listed.
- Audit log: every action the platform records has a label, with areas in the filter and target type names.
- Platform admins' conversation list says "Title hidden" for a withheld title instead of "Private conversation";
  Visibility says who sees the thread.
- Agent Test chat: the header's Shared icon stays on the line with its word.

## Upgrading from v0.1.0

Replace both images (the platform and the runtime, by digest) and restart. There are no migrations and no new
settings. Run `pi-durable-platform doctor` afterwards: it now also checks the agents database.

## Known limitations

Unchanged from [v0.1.0](v0.1.0.md#known-limitations). The [roadmap](../roadmap.md) plans each one, and each has a GitHub
issue with the `roadmap` label.

## Images

| Image | What |
|---|---|
| `ghcr.io/ncecere/pi-durable-platform` | The platform (distroless, UID 65532, read-only root filesystem) |
| `ghcr.io/ncecere/pi-durable-platform-runtime` | The agent runtime (Node 22, UID 10001, read-only root filesystem with a writable `/tmp`) |

Both are tagged `v0.1.1` and `latest`, for linux/amd64 and linux/arm64. Deploy by digest. The digests are in the GitHub
Release, its `<image>-v0.1.1.digest.txt` assets and the workflow's job summary.

## Verifying the images

Verify the signatures with [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) **v3.0 or newer**
(keyless, GitHub Actions OIDC):

```sh
cosign verify ghcr.io/ncecere/pi-durable-platform@sha256:<digest> \
  --certificate-identity https://github.com/ncecere/pi-durable-platform/.github/workflows/image.yml@refs/tags/v0.1.1 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
cosign verify ghcr.io/ncecere/pi-durable-platform-runtime@sha256:<digest> \
  --certificate-identity https://github.com/ncecere/pi-durable-platform/.github/workflows/image.yml@refs/tags/v0.1.1 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

The SBOM (SPDX) and build provenance are attached to each image as attestations, and the Release carries each image's
SBOM per platform with `checksums.txt`. `pi-durable-platform version` prints `pi-durable-platform 0.1.1 (<commit>)`;
the runtime image is labelled `org.opencontainers.image.version=0.1.1`.
