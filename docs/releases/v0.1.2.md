# Pi Durable Platform v0.1.2

A fix release (2026-10-19) on top of [v0.1.1](v0.1.1.md): two console fixes. No database migrations (still `00016`), no
configuration changes.

## What changed

**Fixed**

- **A connecting app's logo shows.** An app that connects with OAuth Connect can publish a logo. The approval screen,
  Account › Connected apps and a person's admin page showed a broken image, because the console's
  Content-Security-Policy allows images only from the platform itself. The platform now fetches the logo (public
  addresses only, https only, no redirects, at most 256 KiB, PNG, JPEG, GIF or WebP verified by their bytes, never SVG),
  caches it for an hour and serves it from its own origin at `GET /v1/oauth/client-logo?client_id=…` (signed-in people
  only, rate limited). The request never carries a URL, so it can't be used to fetch arbitrary addresses (#25).
- **The agent page's status badge follows the agent.** After a message woke a hibernated agent from another session or an
  app, the badge kept saying "Hibernating" until the next poll or a reload. The page now follows the agent's events
  (#27).

## Upgrading from v0.1.1

Replace both images (the platform and the runtime, by digest) and restart. There are no migrations and no new settings.

## Known limitations

Unchanged from [v0.1.0](v0.1.0.md#known-limitations). The [roadmap](../roadmap.md) plans each one, and each has a GitHub
issue with the `roadmap` label.

## Images

| Image | What |
|---|---|
| `ghcr.io/ncecere/pi-durable-platform` | The platform (distroless, UID 65532, read-only root filesystem) |
| `ghcr.io/ncecere/pi-durable-platform-runtime` | The agent runtime (Node 22, UID 10001, read-only root filesystem with a writable `/tmp`) |

Both are tagged `v0.1.2` and `latest`, for linux/amd64 and linux/arm64. Deploy by digest. The digests are in the GitHub
Release, its `<image>-v0.1.2.digest.txt` assets and the workflow's job summary.


## Verifying the images

Verify the signatures with [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) **v3.0 or newer**
(keyless, GitHub Actions OIDC):

```sh
cosign verify ghcr.io/ncecere/pi-durable-platform@sha256:<digest> \
  --certificate-identity https://github.com/ncecere/pi-durable-platform/.github/workflows/image.yml@refs/tags/v0.1.2 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
cosign verify ghcr.io/ncecere/pi-durable-platform-runtime@sha256:<digest> \
  --certificate-identity https://github.com/ncecere/pi-durable-platform/.github/workflows/image.yml@refs/tags/v0.1.2 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

The SBOM (SPDX) and build provenance are attached to each image as attestations, and the Release carries each image's
SBOM per platform with `checksums.txt`. `pi-durable-platform version` prints `pi-durable-platform 0.1.2 (<commit>)`;
the runtime image is labelled `org.opencontainers.image.version=0.1.2`.
